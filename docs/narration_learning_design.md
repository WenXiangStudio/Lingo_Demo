# 英语口语自述分析与学习机制（最终版）

---

## 一、总体流程

用户提交英文口语自述 → 功能1：完整原样转写（保留原始转写） → 用户提交逐句中文翻译并确认 → 系统生成目标正确英文表达并请用户确认 → 以“中文材料 + 目标正确英文表达”为锚，对原始转写进行对齐与清洗 → 功能2：四板块处理 → 功能3：沉淀学习库 → 复习机制 → 进步追踪

---

## 二、功能1：口语自述转写

- **输入**：用户提交一段英文口语自述。
- **处理**：将用户的口语自述**完整且原样**转写下来，并**保留原始转写**。
- **输出**：口语自述的原始转写文本。

原始转写必须保留，用于后续错误分析。清洗后的版本另存，不替代原始转写。

### 转写置信度与异常处理

#### 1. 转写置信度分级

| 级别 | 含义 | 处理方式 |
|---|---|---|
| 高置信度 | 转写基本确定 | 直接进入后续流程 |
| 中置信度 | 个别词或片段不确定 | 标注不确定片段，请用户确认 |
| 低置信度 | 多处不确定或整体不可靠 | 必须用户确认或重录，否则不进入后续分析 |

置信度来源：音频清晰度、口音匹配度、语速连读、背景噪音、专有名词、中文替代词位置、与中文材料的对齐程度等。

#### 2. 异常类型与处理策略

| 异常类型 | 示例 | 处理策略 |
|---|---|---|
| 个别词不确定 | 听不清是 “walk” 还是 “work” | 标注该词，请用户确认 |
| 片段缺失 | 某句完全没转出来 | 请用户补录或手动补充 |
| 多余内容 | 转出用户没说的词 | 请用户确认后删除 |
| 中文替代词识别不清 | “苹果”听成“平果” | 结合中文材料对齐，请用户确认 |
| 口音导致误转 | 英式发音被转成美式拼写 | 标注，按用户偏好修正 |
| 背景噪音干扰 | 环境嘈杂导致整段不可靠 | 建议重录 |
| 专有名词错误 | 人名、地名、品牌名转错 | 标注，请用户确认正确拼写 |

处理原则：

1. **高置信度**：直接通过；
2. **中置信度**：标注不确定片段，请用户确认后通过；
3. **低置信度**：必须用户确认或重录，否则不进入后续分析；
4. **用户确认后**：修正转写，原始转写保留，修正版用于后续流程；
5. **用户不确认**：该片段标记“待确认”，后续分析跳过或标注不确定。

#### 3. 与中文材料的关系

- 中文材料用于判断用户意图；
- 转写置信度用于判断英文形式是否可靠；
- 若中文材料与转写严重不匹配，系统优先怀疑转写错误，并请用户确认；
- 若中文材料本身也有误，进入反馈闭环处理。

#### 4. 转写日志

单独设**转写日志**，记录：

- 原始转写；
- 修正后转写；
- 置信度分级；
- 不确定片段及原因；
- 用户确认结果；
- 是否重录；
- 与中文材料的对齐情况。

用途：优化转写模型、分析高频误转类型、为用户提供转写质量反馈。

#### 5. 转写后用户手动删除无效内容（可选项）

- 系统完成转写那一刻，用户可自行删除无效内容或干扰项；
- 例如：重复、停顿、语气词、半截句、无关内容；
- 该操作**可选**，用户不做也可以；
- 用户手动删除的版本作为“用户清洗版转写”，用于后续流程；
- **原始转写仍然保留**；
- 系统自动清洗仍可继续执行，两者不冲突；
- 用户手动删除的记录存入转写日志。

## 三、前置必须材料：逐句中文翻译

在进入功能2四板块处理之前，用户必须提交与英文口述**逐句对应**的中文翻译，并确认该翻译准确反映自己想表达的意思。

### 核心定位（双轨制标准）

| 分析维度 | 唯一参考标准 | 说明 |
|---|---|---|
| 用户意图 | 中文材料 | 用户想表达什么，以用户提交并确认的中文翻译为最高权威 |
| 英文正确性 | 英语规则 | 语法、用法、搭配、地道性，以英文规则为准 |
| 冲突处理 | 用户确认 | 当中文材料与英文口述严重矛盾时，系统发起确认，不自行猜测 |

- **中文材料 = 用户意图的唯一参考标准。**
- **英文规则 = 英文正确性的唯一参考标准。**
- 中文材料本身有误或与英文口述冲突时，系统通过冲突检测提示用户确认，修正后再继续分析。
- 该中文翻译材料为**必须项**，不是可选项。

---

## 四、分析锚点：目标正确英文表达

系统根据用户提交并确认的中文材料，生成**目标正确英文表达**，并请用户确认。

- **作用**：作为后续分析、清洗、纠错的核心基准。
- **确认**：用户确认后，该表达成为“用户意图”在英文形式上的锚点。
- **变体**：同一中文意图可能有多种正确英文表达，系统可生成推荐表达，允许用户确认或选择可接受变体。
- **概念区分**：
  - **目标正确英文表达**：分析基准。
  - **口述材料正确式**：最终输出给用户的修正版，通常与目标一致，也可根据用户实际口述微调。

---

## 五、对齐与清洗

以“中文材料 + 目标正确英文表达”为锚，辅以英文规则，对原始转写进行对齐与清洗，得到**规范化口语转写**。

### 口语特征分类处理

| 类型 | 处理方式 |
|---|---|
| 无意义重复：I I have | 清洗时去除 |
| 停顿、语气词：uh, um, well | 清洗时去除 |
| 自我纠正：I have a apple, no, an apple | 清洗后保留正确部分，错误痕迹进错误分析 |
| 强调性重复：very very good | 保留，不算干扰 |
| 半截句：I want to… never mind | 结合中文材料判断意图，必要时请用户确认 |

- **原始转写保留**，不因清洗而删除。
- 清洗结果用于对齐与最终正确式生成；错误分析同时参考原始转写与规范化转写。

## 六、功能2：四板块处理

系统收到用户口语自述材料、确认后的中文翻译、目标正确英文表达及规范化转写后，进入四个板块处理。

### 1. 错误分析

**前置必须材料**：逐句中文翻译、目标正确英文表达、规范化转写。

**正式功能：**

核心有两个职能：

1. **分析有什么错误**  
   分析错误类型，例如：拼写错误、语法错误、用法错误等。
2. **给出错误类型的正确表达**  
   将上述错误改写成正确表达，并附上改写原因。

**特别说明一：中文替代词本身不算错误**

- 不要将用户的中文与英文结合当成错误。
- 例如：用户说 **I have an 苹果**，不要将这种表达当成“中英文混用错误”。
- 这类中文替代词不纳入错误分析，不应被判为拼写错误、语法错误、用法错误或中英文混用错误。
- 它的作用是作为“用户不会该英文单词”的信号，进入单词收集。

**特别说明二：中文替代词周围的英文用法，仍以英文规则分析**

- 中文替代词本身不算错误，但**中文替代词周围的英文语法、用法，仍然按照英文规则正常分析**。
- 示例：用户说 **I have a 苹果**。
  - “苹果”是中文替代词 → 进单词收集，不算错误。
  - “a”是英文冠词 → 后面实际对应英文单词 **apple**，元音音素开头 → 应使用 **an** → 因此 **“a”算错误**。
  - 正确式应为：**I have an apple.**
  - 因中文替代词暴露的语法点同步记录进知识点库。

**错误分级（四级）**

| 级别 | 名称 | 说明 | 示例 |
|---|---|---|---|
| A级 | 阻断理解/核心错误 | 严重影响意思表达，必须优先改 | 时态错导致时间错、主谓不一致、关键介词错、词序错 |
| B级 | 明显语法/用法错误 | 不影响理解，但明显不对 | 冠词 a/an 错、单复数错、介词搭配错 |
| C级 | 不地道/可优化 | 语法没错，但不自然、不地道 | 用词生硬、表达啰嗦、中式英语 |
| D级 | 口语特征/干扰项 | 不是错误，只是口语现象 | 重复、停顿、语气词、半截句、自我纠正 |

**处理规则**

- **A、B、C 三级所属的错误分析必须全部列出。**
- **C级需要单独列出来。**
- **D级不进入错误分析，不必显式列出，仅归入知识点库作为口语特征处理记录。**
- **不根据用户水平动态调整分级。**
- 中文替代词本身不算错误；其周围英文用法按 A/B/C 正常分析。

**优先级排序规则**

同级内部，按以下顺序排：

1. 是否阻断理解：越影响沟通越靠前；
2. 是否高频重复：用户反复犯的错优先；
3. 是否与中文替代词相关：相关错误优先；
4. 是否影响后续表达：冠词、时态等基础项优先。

**展示方式**

- A级错误（优先修改）
- B级错误（建议修改）
- C级错误（可优化，单独列出）
- D级口语特征不显式列出，仅归入知识点库。

每条可包含：原句、问题、正确表达、原因。

### 2. 单词收集

- **核心职能**：收集用户英语口述材料中，那些用中文替代的、用户不知道的英文单词。
- **示例**：  
  用户说：I have an 苹果  
  因为用户不知道“苹果”的英文，于是将 **Apple** 记录到该板块中。

#### 中文替代词的边界（定稿）

**核心定义：**

> **中文替代词 = 在英文口述中，用户用中文说出的、原本应该用英文表达的内容。**

关键：原本应该用英文表达，且英文有对应表达，才叫“替代词”。

**按单位分：**

| 单位 | 示例 | 处理方式 |
|---|---|---|
| 单词 | I have an 苹果 | 进单词收集 |
| 短语/固定表达 | I 不知道 how to say it | 进单词收集，标记为“短语” |
| 完整句子 | I think 今天天气很好 | 不进单词收集，由目标正确英文表达直接给出完整英文 |

**按词性分：**

| 类别 | 是否收 | 说明 |
|---|---|---|
| 名词 | 收 | 苹果 → apple |
| 动词 | 收 | 跑 → run |
| 形容词 | 收 | 高兴 → happy |
| 副词 | 收 | 很快 → quickly |
| 数词 | 收 | 三个 → three |
| 量词 | 收 | 一杯 → a cup of |
| 代词 | 收 | 他们 → they |
| 介词 | 收 | 在……里 → in |
| 连词 | 收 | 和 → and |
| 冠词 | 收，标记为功能词 | 一个 → a/an |
| 助动词 | 收 | 能 → can |
| 专有名词 | 收，标记为专有名词 | 北京 → Beijing |
| 日期/时间 | 收 | 星期一 → Monday |
| 语气词/感叹词 | 视情况 | 若英文有对应，收；若无对应，标记为“无对应”，不强行收 |

**功能词的特殊处理：**

- 进单词收集；
- 同步进知识点库；
- 标记为“功能词”。

**专有名词、数字、日期：**

| 类型 | 示例 | 对应英文 | 处理 |
|---|---|---|---|
| 专有名词 | 北京 | Beijing | 收，标记专有名词 |
| 数字 | 三 | three | 收，标记数词 |
| 日期 | 星期一 | Monday | 收，标记时间词 |
| 时间 | 下午 | afternoon | 收，标记时间词 |

**一个中文对应多个英文时：**

- 结合中文材料和上下文，由系统确定一个最可能的英文表达；
- 若无法确定，请用户选择；
- 不同英文表达分开建条，不合并。

**不算中文替代词的情况：**

1. 英文里没有对应表达的中文语气词，如“吧”“嘛”“呗”，不强行收；
2. 用户中文替代的是一个完整句子，不进单词库，由目标正确英文表达处理；
3. 用户用中文说了英文里也常用的外来词，如 sushi、tofu，若用户说的是英文词，不算替代；
4. 用户中英混用但英文词正确、中文词是冗余重复，如 “I have an apple 苹果”，结合中文材料判断，若“苹果”是重复，可不算替代，但系统应提示用户确认。

### 3. 知识点汇总

**核心原则**

- 只汇总与本次用户输出**直接相关、且具有学习价值**的知识点。
- **不做全量罗列，只做相关筛选。**
- 从“用户实际表达”和“目标正确表达”的差异中提取，而非从目标句无差别拆解。

**知识点来源**

| 来源 | 说明 | 示例 |
|---|---|---|
| 错误驱动 | 用户犯错的点 | a 苹果 → 冠词 a/an |
| 单词驱动 | 中文替代词暴露的英文知识 | 苹果 → apple，元音音素开头 |
| 优化驱动 | C级不地道表达背后的知识点 | very like → like very much |
| 口语特征记录 | D级口语现象，仅作参考 | 重复、停顿、自我纠正 |

- 前三个进入正式知识点汇总；第四个只作为口语特征记录，不作为正式学习任务。

**知识点分级（三级）**

| 级别 | 名称 | 说明 | 是否进入复习 |
|---|---|---|---|
| 核心知识点 | 与本次错误直接相关 | 用户必须优先掌握 | 是 |
| 关联知识点 | 支撑核心知识点的周边知识 | 帮助理解，不强制 | 可选 |
| 拓展知识点 | 更地道的表达或可选变体 | 提升用，不强制 | 否 |

**筛选规则**

1. 只记录与错误、中文替代词、C级优化直接相关的知识点。
2. 用户已经正确且无争议的基础结构，不记录。
3. 同一知识点重复出现时，合并，不重复建条。
4. 核心知识点优先进入复习；关联和拓展只做记录。
5. D级口语特征单独分区，不算正式知识点，不进入复习任务。
6. 不按用户水平动态调整知识点范围，保持规则稳定，只按相关性筛选。

**去重与合并**

- 每个知识点有唯一标识；
- 多次出现时，合并为一条；
- 记录：首次出现时间、最近出现时间、出现次数、关联错误级别、掌握状态；
- 如果用户已经掌握，可以降频或标记为已掌握，不再进入复习队列。

### 4. 口述材料正确式

- **核心职能**：将用户错误的英语口述改写成正确的表达。
- **改写依据**：
  - 语义必须与中文材料所表达的用户意图一致；
  - 形式必须符合英文规则；
  - 通常以目标正确英文表达为基准，可根据用户实际口述微调。
- **改写后自检**，主要检查三点：
  1. 是否仍有错误；
  2. 是否地道；
  3. 是否偏离中文原意。

#### 自检机制（定稿）

**自检执行主体：**

- **系统自检 + 用户最终确认。**
- 系统生成正确式后，自动执行自检流程。
- 自检通过后，展示给用户，用户做最终确认。
- 用户如有异议，进入反馈闭环。

**自检检查项（五项）：**

| 检查项 | 具体内容 |
|---|---|
| 1. 是否仍有错误 | 语法、拼写、用法、搭配、标点 |
| 2. 是否地道 | 语域是否自然、是否符合英语表达习惯、是否中式英语 |
| 3. 是否偏离中文原意 | 语义是否等价、语气是否一致、重点是否保留 |
| 4. 是否与目标正确英文表达一致 | 若不一致，偏离是否合理、是否经过用户确认 |
| 5. 是否保留用户原口述的合理风格 | 不把用户的口语风格全部改成书面语 |

**地道性标准：**

- **默认标准：地道英式英语，口语为主。**
- 拼写、用词、语法、搭配，优先按英式英语判断。
- 语域默认与用户原口述场景一致，偏口语。
- 允许用户手动设置偏好，比如改成美式、正式、学术等，但**默认是英式**。
- 若用户未设置，一律按地道英式口语处理。

地道性判断来源：规则库、模型判断；若无法确定，标记“待确认”，不强行输出。

**自检流程：**

1. 系统生成口述材料正确式草稿。
2. **自检1：语义检查** —— 对比中文原意，确认语义一致。
3. **自检2：形式检查** —— 对比英文规则，确认无语法、用法错误。
4. **自检3：地道性检查** —— 按英式口语默认标准判断是否自然。
5. **自检4：一致性检查** —— 与目标正确英文表达对比，确认偏离合理。
6. **自检5：风格检查** —— 确认未过度改写用户原口述的合理风格。
7. 若发现问题，自动修改，最多迭代 **3 轮**。
8. 若 3 轮后仍无法通过，标记“待用户确认”，并说明问题。
9. 生成**自检报告**，附在正确式旁边。
10. 用户确认或提出异议。

**自检报告内容：**

- 检查项通过情况；
- 发现的问题及修改说明；
- 无法确定的问题；
- 与目标正确英文表达的差异说明；
- 地道性判断依据；
- 迭代次数。

**自检日志：**

- 每次自检记录存入**自检日志**。
- 用途：优化系统判断、减少同类问题、分析高频错误。
- 与反馈日志分开存储。

#### 目标表达与正确式的最终输出（定稿）

**用户最终看到的三件套：**

1. **原口述（原始转写）**
2. **口述材料正确式（修正版）**
3. **差异说明（改了哪里、为什么改）**

**逐句对照展示：**

| 原口述 | 正确式 |
|---|---|
| I have a 苹果 | I have an apple |
| I go park yesterday | I went to the park yesterday |

**目标正确英文表达：**

- 默认不直接展示，放在“详情”里可折叠查看；
- 如果目标表达和正确式有显著差异，差异说明里要解释。

**多个正确表达时：**

- 系统生成**一个主推荐正确式**；
- 可选提供**1–2个可接受变体**；
- 变体标注差异：冠词、语序、语气、正式程度；
- 用户可选择确认其中一个作为最终正确式；
- 若用户不选，默认用主推荐。

**最终输出页结构：**

1. 原口述 vs 正确式对照
2. 错误分析（A/B/C 级，全部列出，C级单独列）
3. 单词收集（中文替代词 → 英文）
4. 知识点汇总（核心/关联/拓展）
5. 正确式自检报告
6. 可选：目标正确英文表达（折叠）

**UI 高亮标注规则：**

- 在“原口述 vs 正确式”逐句对照区域，对差异部分进行**高亮/突出显示**。
- **中文替代词与对应英文**：如“苹果” ↔ “apple”，用同一种高亮样式。
- **英文错误与正确形式**：如“go” ↔ “went to”、“park” ↔ “the park”，对差异部分分别高亮。
- **不同类型可用不同颜色/样式区分**：
  - 中文替代词：一种颜色；
  - 语法错误：另一种颜色；
  - 缺失/添加：插入标记或不同样式；
  - 不地道表达：可优化样式。
- 高亮仅用于 UI 展示，不改变文本本身。
- 用户可点击高亮部分，查看对应原因，并与错误分析、单词收集、知识点汇总联动。
- 原始转写和正确式仍完整保留，高亮只是视觉辅助。

## 七、功能3：建立学习库

### 1. 单词学习库

**去重与掌握状态（定稿）**

**核心原则：**

> **以英式原形为唯一标识，同词合并，记录出现次数与掌握状态。**

**去重规则：**

- 以**英式英语原形**作为唯一标识。
- 同一个英文词多次出现时：不重复建条；合并为一条；更新出现次数、最近出现时间；保留历史来源记录。
- 同一个中文词可能对应多个英文时，分开建条。
- 词形变化归原形：如 apples 归 apple、went 归 go。

**单词库字段：**

- 英文词条（英式原形）
- 中文替代表达（一个或多个）
- 词性
- 音标（可选）
- 首次出现时间
- 最近出现时间
- 出现次数
- 来源口述记录 ID
- 掌握状态
- 复习记录
- 真实使用成功次数
- 真实使用失败次数
- 用户异议/确认标记
- 是否移出复习队列
- 备注

**掌握状态（六档）：**

| 状态 | 判定条件 |
|---|---|
| 新收录 | 刚进入单词库 |
| 复习中 | 间隔复习通过至少1次 |
| 待验证 | 间隔复习通过2次以上，但未在真实口述中使用 |
| 已掌握 | 在真实口述中自然、正确使用至少1次 |
| 疑似遗忘 | 已掌握后，再次用中文替代同一个词，或真实使用失败 |
| 稳定掌握 | 近三个月内无遗忘/错误触发，移出复习队列，但保留在单词库 |

**真实使用触发：**

- 后续口述中自然、正确用出该英文词 → **真实使用成功**；
- 后续口述中再次用中文替代同一个词 → **真实使用失败**；
- 真实使用成功 = 最高权重，可直接跳到“已掌握”；
- 真实使用失败 = 降级或提高复习频率。

**移出复习队列规则：**

- 已掌握内容暂时**只降频，不移出复习队列**；
- **必须同时满足两个条件，才可在三个月后移出复习队列：**
  1. **三个月内被触发过**（复习触发或真实使用触发，至少一次）；
  2. **该触发无遗忘、无错误**。
- 若三个月内从未被触发，则**继续留在复习队列**，不自动移出。
- 移出后仍保留在单词库；
- 若后续再次被触发为遗忘/错误，可重新进入复习队列。

**与知识点库的分工：**

- **单词库**：只存词条、中文替代、掌握状态、出现记录；
- **知识点库**：存该词的用法、搭配、语法点、音变规则等；
- 单词的用法、搭配、语法点**归知识点库**，不在单词库重复展开。

**用户异议：**

- 用户可以说“我会这个词”；
- 系统解释后，用户最终确认；
- 确认后**标记降频**；
- 异议记录进入反馈日志。

**单词库日志：**

单独设**单词库日志**，记录：合并记录、状态变更、真实使用成功/失败、用户确认与异议、移出/重新进入复习队列、其他关键历史。

### 2. 知识点库

- 用于收录每次用户口述材料中所涉及的英语知识点。
- 只收录经过相关筛选的正式知识点，按**核心/关联/拓展**三级分类。
- D级口语特征单独记录，不进入正式知识点，不进入复习任务。
- 同一知识点多次出现时，合并记录，并记录出现次数、首次/最近出现时间、关联错误级别、掌握状态。
- 不按用户水平动态调整知识点范围。

## 八、复习机制（定稿）

### 1. 复习对象：三类分开处理

| 类型 | 来源 | 复习要求 |
|---|---|---|
| 单词 | 单词学习库 | 必复习 |
| 核心知识点 | 知识点库·核心 | 必复习 |
| 关联/拓展知识点 | 知识点库·关联/拓展 | 可选，不强制 |

D级口语特征不进入复习。

### 2. 复习触发：双触发

**间隔触发：**

- 新收录内容 → 第1天、第3天、第7天、第14天、第30天进入复习队列；
- 每次复习结果决定下一次间隔：通过则拉长，不通过则缩短。

**真实使用触发：**

- 用户在**下一次口语自述**中，自然用出某个已收录单词或知识点 → 标记为**真实使用成功**；
- 用户再次用中文替代同一个词，或再犯同一个知识点错误 → 标记为**真实使用失败**，提高复习优先级。

### 3. 复习形式：三层递进

| 层级 | 形式 | 目标 |
|---|---|---|
| 第一层：识别 | 看中文，说英文；看错误句，说正确句 | 能回忆起来 |
| 第二层：应用 | 给一个与用户原口述相关的新语境，用目标词/知识点造句 | 能套用 |
| 第三层：真实输出 | 在下次口述中自然使用 | 真正掌握 |

三层都通过，才算“已掌握”。

### 4. 真实输出的触发方式（定稿）

**定义：**

> **真实输出 = 用户在自然口述中，未经系统提示，自发、正确、自然地用出了已收录的单词或知识点。**

**主要触发方式：下次口述自动检测**

- 用户下一次提交口述材料时，系统自动扫描是否用到了已收录的单词或知识点；
- 用了且正确自然 → 真实使用成功；
- 再次用中文替代同一个词 → 真实使用失败；
- 再犯同一个知识点错误 → 真实使用失败；
- 没用 → 不触发，继续间隔复习。

**辅助触发：主动真实输出任务（可选）**

- 系统提示用户用某些词/知识点说一段话；
- 用户口述后系统检测；
- 标记为“引导式真实输出”，算真实输出，但权重略低于自然口述中的真实使用；
- 掌握状态可升级，但“已掌握”标记可附注“引导式”；
- 若后续自然口述中再次正确使用，则升级为完全“已掌握”。

**不触发的情况：**

- 系统直接问“apple 什么意思”，用户回答 → 识别，不是真实输出；
- 系统给中文，用户翻译 → 应用，不是真实输出；
- 用户专门背单词 → 不算；
- 用户硬塞目标词，语境不自然 → 不算。

**长期不口述的兜底：**

- 间隔复习照常进行；
- 掌握状态停留在“待验证”，不会自动升到“已掌握”；
- 三个月无遗忘/错误触发 → 按移出规则处理（见上）；
- 若用户重新开始口述，已移出内容可重新进入复习队列；
- 引导式真实输出任务可作为可选提醒，但不强制。

### 5. 掌握度判定：以真实使用为最高标准

| 状态 | 判定条件 |
|---|---|
| 新收录 | 刚进入学习库 |
| 复习中 | 间隔复习通过至少1次 |
| 待验证 | 间隔复习通过2次以上，但未在真实口述中使用 |
| 已掌握 | 在真实口述中自然、正确使用至少1次 |
| 疑似遗忘 | 已掌握，但后续真实口述中再次犯错或用中文替代 |

- **真实使用成功** = 最高权重，可直接从“待验证”跳到“已掌握”；
- **真实使用失败** = 降级或提高复习频率。

### 6. 复习队列规则

**每天复习量：** 不限量。

**优先级排序：**

1. 真实使用失败的 → 最高；
2. 即将遗忘的（间隔到期） → 高；
3. 高频错误的 → 中；
4. 新收录的 → 中；
5. 关联/拓展 → 低。

**已掌握内容的处理：**

- **暂时只降频，不移出复习队列。**
- 移出标准：必须三个月内被触发过且无遗忘/错误，才可移出；从未触发则继续留在队列。
- 移出后仍保留在学习库中，若后续再次被触发为遗忘/错误，可重新进入复习队列。

### 7. 与主流程的对接

1. 主流程产出 → 单词库、知识点库；
2. 复习机制 → 从库中取内容，安排复习；
3. 复习结果 → 回写掌握状态；
4. 下次口述 → 真实使用检测，再次回写；
5. 已掌握内容 → 降频，满足条件后移出复习队列；
6. 疑似遗忘内容 → 重新进入复习队列。

形成闭环：**口述 → 分析 → 收录 → 复习 → 真实使用 → 再分析 → 再收录**

## 九、用户反馈与异议闭环（定稿）

### 1. 基本原则

- **每个环节都可异议。**
- **系统先解释，用户最终确认，但保留原始判断记录。**
- **用户确认修改后，回写学习库或复习队列。**
- **用户确认后，系统不再反复推翻。**
- **异议记录单独存一个反馈日志，用于后续优化系统。**

### 2. 可异议环节

| 环节 | 可异议内容 |
|---|---|
| 转写 | 转写错了、漏了、多了 |
| 中文翻译 | 中文不是这个意思 |
| 目标正确英文表达 | 翻译偏了、语气不对、不是我想说的 |
| 错误分析 | 判错了、级别不对、原因不对 |
| 单词收集 | 我会这个词、这个词不对 |
| 知识点汇总 | 这个知识点我会、分类不对 |
| 口述材料正确式 | 仍不对、不地道、偏离原意 |
| 复习判定 | 我已经会了、真实使用判定有误 |

### 3. 异议处理流程

1. 用户提出异议。
2. 系统先解释判断依据。
3. 用户可选择：接受系统解释；坚持异议并给出理由；修改为自定义结果。
4. 最终以用户确认为准。
5. 系统保留原始判断记录。
6. 用户确认修改后，回写到对应位置。
7. 用户确认后，系统不再反复推翻。

### 4. 反馈日志

- 所有异议记录单独存入**反馈日志**。
- 用途：后续优化系统判断、减少同类误判、分析用户偏好。

## 十、进步追踪（定稿）

### 1. 追踪维度（五类）

| 维度 | 追踪内容 |
|---|---|
| 错误趋势 | A/B/C 级错误数量、比例、类型变化 |
| 单词掌握 | 新增数、已掌握数、真实使用成功数 |
| 知识点掌握 | 核心/关联/拓展知识点掌握状态变化 |
| 真实使用 | 已收录内容在后续口述中被自然用出的次数 |
| 表达质量 | 口述长度、句子复杂度、中文替代词数量变化 |

其中，**真实使用**为最高价值指标。

### 2. 时间维度（三层）

1. **单次追踪**：本次口述与上次相比如何。
2. **短期趋势**：最近 7 天 / 30 天变化。
3. **长期趋势**：最近 3 个月 / 半年变化。

### 3. 展示方式

- **趋势优先，不搞绝对分数。**
- 展示：趋势图、本次 vs 上次、最近 7 天 vs 前 7 天。
- 展示：里程碑、掌握状态变化、反馈日志摘要。
- 正向表达，避免压力式表达。
- 尽量结合材料难度看趋势。

### 4. 与复习机制联动

- 复习通过 → 掌握状态提升 → 进步追踪记录；
- 真实使用成功 → 跳到“已掌握” → 进步追踪记录；
- 真实使用失败 → 状态降级 → 进步追踪记录；
- 三个月无遗忘/错误触发 → 移出复习队列 → 进步追踪记录为“稳定掌握”。

### 5. 推送与自定义

- **每周一次摘要报告。**
- **每月一次完整报告。**
- 推送频率允许用户自定义。
- 允许用户自定义追踪目标。

### 6. 避免的问题

1. 不用单次表现判断进步；
2. 不忽略材料难度；
3. 不给用户压力；
4. 不只追踪错误，也追踪中文替代词减少、句子变长变复杂、真实使用增加、表达更地道。

## 十一、用户长期不使用的处理（定稿）

### 1. 短期不活跃 vs 长期不使用

| 情况 | 定义 | 处理方向 |
|---|---|---|
| 短期不活跃 | 1–4 周未使用 | 正常保留，不特殊处理 |
| 长期不使用 | 超过 1–3 个月未登录、未口述、未复习 | 进入休眠与激活机制 |

### 2. 核心原则

1. 不自动删除用户数据；
2. 不误判掌握状态；
3. 复习队列不无限堆积；
4. 用户回来后可恢复；
5. 提醒可选、可关闭。

### 3. 复习队列：休眠与激活

**休眠触发：**

- 用户超过 **60 天**未登录、未口述、未复习；
- 复习队列整体转入**休眠状态**；
- 休眠期间：不主动推送复习任务；不自动移出任何词或知识点；掌握状态保持不变；数据完整保留。

**激活触发：**

- 用户重新登录或重新提交口述材料；
- 复习队列自动激活；
- 按优先级重新排序；
- 休眠期间积累的到期任务，按优先级分批展示。

**与“三个月移出”规则的关系：**

- 休眠期间，三个月移出规则**暂停计算**；
- 休眠期间没有触发，按规则不移出；
- 激活后重新开始计算。

### 4. 掌握状态

- 已掌握的内容**不自动降级**；
- 但可标记为 **“待重新验证”**；
- 用户重新使用后，若在真实口述中再次正确使用 → 恢复“已掌握”；
- 若再次犯错或用中文替代 → 降级为“疑似遗忘”，提高复习优先级。

### 5. 进步追踪

- 长期不使用期间，进步追踪数据完整保留；
- 趋势图可显示“中断”；
- 用户回来后的第一次口述，作为新的基线；
- 短期趋势重新从最近 7 天 / 30 天开始计算；
- 长期趋势可保留历史，但标注“中断期”。

### 6. 数据保留

- 长期不使用，账户未注销：数据继续保留；
- 不自动删除、不自动匿名化、不自动清空复习队列；
- 若用户超过 **2 年**未登录，可发送一次提醒；
- 提醒后仍不登录，删除以用户主动注销为准。

### 7. 提醒机制

- 可选，默认开启，用户可关闭；
- 频率建议：30 天未使用 → 一次轻提醒；60 天未使用 → 一次提醒 + 休眠通知；90 天未使用 → 最后一次提醒；之后不再频繁打扰。
- 提醒内容不施压。

### 8. 重新激活后的流程

1. 用户重新登录或提交口述；
2. 复习队列激活；
3. 掌握状态标记“待重新验证”的内容进入验证队列；
4. 进步追踪建立新基线；
5. 正常进入转写、分析、四板块流程；
6. 真实使用触发重新开始工作。

## 十二、隐私与数据安全（定稿）

### 1. 核心原则（六条）

1. **最小必要**：只收集完成功能所必需的数据。
2. **用户知情**：明确告知收集什么、为什么、存多久、给谁用。
3. **用户控制**：可查看、导出、更正、删除、撤回同意。
4. **默认安全**：传输加密、静态加密、访问控制。
5. **默认不用于训练**：可识别个人数据默认不用于模型优化。
6. **可删除可匿名化**：用户注销后，数据删除或匿名化。

### 2. 需要保护的数据类型

| 数据类型 | 敏感度 |
|---|---|
| 口语音频 | 最高 |
| 原始转写 | 高 |
| 修正后转写 | 高 |
| 中文翻译 | 高 |
| 目标正确英文表达 | 中 |
| 错误分析结果 | 中 |
| 单词学习库 | 中 |
| 知识点库 | 中 |
| 复习记录 | 中 |
| 反馈日志 | 中 |
| 自检日志 | 低 |
| 转写日志 | 中 |
| 进步追踪数据 | 中 |
| 用户偏好 | 低 |

### 3. 音频处理

- **默认：转写完成后删除音频**；
- 用户可手动选择**保留音频**，用于回听复盘；
- 若保留，必须加密存储，并允许随时删除；
- 若用于模型优化，必须单独同意，且去标识化；
- 声纹类生物识别信息，不单独提取、不单独存储。

### 4. 存储与处理

- **传输加密**：TLS；
- **静态加密**：AES-256 或同等级；
- **访问控制**：最小权限；
- **审计日志**：记录谁在何时访问了什么数据；
- **本地优先**：能端侧处理的，尽量端侧处理；
- **云端处理**：必须云端时，处理后不长期留存原始音频。

### 5. 用户权利

用户应可：查看自己的数据；导出数据；更正错误数据；删除单条记录；删除全部数据；注销账户；撤回同意；关闭个性化分析；关闭进步追踪；关闭数据用于优化。

### 6. 数据用于优化

- **默认不将可识别个人内容用于模型训练**；
- 若使用，需**单独同意**；
- 使用前**去标识化或聚合**；
- 允许用户随时退出；
- 反馈日志、自检日志、转写日志用于优化时，也需去标识化。

### 7. 第三方与共享

- **不向第三方出售用户数据**；
- 第三方服务商需签数据处理协议；
- 跨境传输需符合当地法规；
- 若使用云服务、语音识别服务，需明确告知用户；
- 具体合规需法律顾问确认。

### 8. 删除与保留期限

| 数据 | 保留期限 |
|---|---|
| 音频 | 转写后默认删除；用户选择保留则存至用户删除 |
| 原始转写/修正转写 | 账户存续期间保留 |
| 中文翻译/目标英文/正确式 | 账户存续期间保留 |
| 单词库/知识点库 | 账户存续期间保留 |
| 复习记录/进步追踪 | 账户存续期间保留 |
| 反馈日志/自检日志/转写日志 | 去标识化后可用于优化，保留期限另定 |
| 注销账户后 | 30天内删除或匿名化；备份最长90天 |

### 9. 未成年人

- 需监护人同意；
- 默认关闭数据用于优化；
- 默认不保留音频；
- 提供更严格删除机制。

### 10. 配套文件

- 单独设**隐私政策**；
- 单独设**同意记录**。

## 十三、机制总结

这套机制可以概括为：

1. **转写**：完整原样记录用户英文口语自述，保留原始转写；
2. **锚定意图**：用户必须提交逐句中文翻译并确认，作为用户意图的唯一参考标准；
3. **生成目标**：系统根据中文生成目标正确英文表达，用户确认后作为分析锚点；
4. **清洗对齐**：以“中文 + 目标正确英文”为锚，对原始转写做对齐与清洗，口语特征分类处理；
5. **分析**：通过错误分析、单词收集、知识点汇总、口述材料正确式四个板块处理；
   - 中文材料锚定意图；
   - 英文规则判断形式；
   - 中文替代词本身不算错误，但周围英文用法照常分析；
   - 错误分A/B/C/D四级，A/B/C全部列出，C级单独列，D级不显式列出，仅进知识点库；
   - 知识点汇总只做相关筛选，不做全量罗列，按核心/关联/拓展三级分类，同一知识点合并记录次数，D级口语特征单独记录，不进入正式知识点和复习任务，不按用户水平动态调整；
6. **沉淀**：将中文替代的英文单词收入单词学习库，将英语知识点收入知识点库；
7. **复习**：双触发、三层递进、真实使用为最高标准、每天不限量、已掌握只降频、满足条件才移出；
8. **反馈**：每个环节可异议，系统解释，用户最终确认，反馈日志单独存；
9. **追踪**：五维度、三层时间、趋势优先、与复习联动、周报月报、可自定义；
10. **自检**：系统自检+用户确认，五项检查，默认地道英式口语，最多迭代3轮，自检报告+自检日志；
11. **异常处理**：转写置信度三级，中置信度标注确认，低置信度必须确认或重录，转写日志单独存；
12. **隐私**：六条核心原则，音频默认删除，加密存储，用户权利，默认不用于训练，注销删除；
13. **长期不使用**：短期正常，长期休眠，60天休眠，激活恢复，三个月移出规则暂停，待重新验证，进步追踪中断标注，提醒可选，超2年仅提醒不自动删除。

最终形成：  
**口语输入 → 原样转写 → 中文翻译锚定意图 → 目标正确英文表达确认 → 对齐清洗 → 四板块分析纠错 → 正确表达输出 → 学习库长期沉淀 → 复习机制 → 进步追踪** 的完整闭环。
